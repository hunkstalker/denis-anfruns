TypeScript comes with a "Swiss Army Knife" of predefined types called **Utility Types**.
They are Generics that take a type and return a modified version.

## `Partial<T>` (Everything optional)

Imagine we have a complete user, but for an update (PATCH), we only send the fields that changed.

<CodeTabs items={[
    {
		label: 'TypeScript',
		code: `interface User {
    id: number;
    name: string;
    email: string;
    password: string;
}

function updateUser(id: number, changes: Partial<User>) {
    // 'changes' is now as if all props had '?'
    // { id?: number; name?: string; email?: string; }
    ...
}

updateUser(1, { name: "Alice" }); // ✅ Valid`,
		lang: 'typescript'
    }
]} />

## `Required<T>` (Everything required)

The opposite of Partial. Removes all `?` from an interface.

## `Pick<T, Keys>` (Pick what you want)

Sometimes we have a huge interface and only need a couple of fields for a small component.

<CodeTabs items={[
    {
		label: 'TypeScript',
		code: `interface Product {
    id: number;
    name: string;
    price: number;
    description: string;
    stock: number;
    ...
}

// We create a new type only with name and price
type ProductLabel = Pick<Product, "name" | "price">;
// { name: string; price: number; }`,
		lang: 'typescript'
    }
]} />

## `Omit<T, Keys>` (Remove what you DON'T want)

The opposite of Pick. Removes specific fields.
Very useful to remove sensitive or unnecessary data.

<CodeTabs items={[
    {
		label: 'TypeScript',
		code: `// A User without the password
type PublicUser = Omit<User, "password">;`,
		lang: 'typescript'
    }
]} />

## `Record<Keys, Type>` (Dictionaries)

This one is a bit special. It serves to create objects where **we don't know the name of the properties**, but we know what values they will have.

Think of a **Phone Book**:
- The **Keys** are names (Strings).
- The **Values** (Type) are numbers (Numbers).

We don't know if you will save "Pepe" or "Maria", but we know the structure will always be `Name -> Number`.

<CodeTabs items={[
    {
		label: 'TypeScript',
		code: `// A normal object requires knowing the keys beforehand
// interface Agenda { pepe: number } // ❌ Impractical

// With Record:
const agenda: Record<string, number> = {};

agenda["Pepe"] = 123456;
agenda["Maria"] = 987654;`,
		lang: 'typescript'
    }
]} />

<Callout type="tip" title="Why not use Map?">
    In modern JavaScript there is `Map`, which is a real dictionary. In TypeScript it would be `Map<string, number>`.

    However, we use `Record` (Objects) 90% of the time because **Objects are converted to JSON automatically**, while `Map`s get lost when sending them to an API.
</Callout>

<CodeTabs items={[
    {
		label: 'Map vs Record',
		code: `// --- Option A: Record (Plain object) ---
// Ideal for saving to a Database or sending to the Frontend
type AgendaRecord = Record<string, number>;

const agenda1: AgendaRecord = {
    "Pepe": 666555444
};

// --- Option B: Map (The "Pro" way) ---
// Ideal for complex internal logic (sets, gets, size...)
type AgendaMap = Map<string, number>;

const agenda2: AgendaMap = new Map();
agenda2.set("Pepe", 666555444); // ✅ TS watches that you pass a number
// agenda2.set("Juan", "hola"); // ❌ Error!`,
		lang: 'typescript'
    }
]} />

### Hands on!

We have a `Todo` interface. Let's use:
1. Create `TodoUpdate` using `Partial` of `Todo`.
2. Create `TodoPreview` using `Pick` of `Todo` (only `title` and `completed`).
3. Create `TodoDictionary` which is a `Record` where the key is `string` and the value is `Todo`.

```ts
interface Todo {
    id: number;
    title: string;
    description: string;
    completed: boolean;
}

// 1. Define 'TodoUpdate' using Partial (Everything optional)
// type TodoUpdate = ...

// 2. Define 'TodoPreview' using Pick (only title and completed)
// type TodoPreview = ...

// 3. Define 'TodoDictionary' using Record
// Key: string (the ID), Value: Todo
// type TodoDictionary = ...

// Tests (Do not touch this)
const testUpdate: TodoUpdate = { title: "Title only" }; // ✅
const testPreview: TodoPreview = { title: "View", completed: false }; // ✅

// ✅ Should allow saving Todo with any string key
const testDiccionario: TodoDictionary = {
    "todo-1": { id: 1, title: "A", description: "D", completed: false },
    "urgent": { id: 2, title: "B", description: "D", completed: true }
};
```

Copy the code and try it in <a href="https://www.typescriptlang.org/play" target="_blank" rel="noopener noreferrer">official TypeScript Playground</a>.
